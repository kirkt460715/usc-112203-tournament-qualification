# 电竞联赛赛制下的晋级偏差与补赛决策

组织方记录积分裁决及已经锁定的资格；先后手及替补记录并不构成额外正式积分。

records 保存可离线使用的合成业务记录。每行一个 UTF-8 JSON 对象，id 在各数据表内唯一，跨表键沿用业务记录中的标识。catalog.json 保存行数及原始文件校验值。

| 记录 | 业务含义 |
| --- | --- |
| teams.jsonl | seed 用于抽签限制，阵容数据用来分析已经开打的比赛。 |
| games.jsonl | slot 是赛季内相对排期。known_slot 是原排期已知的时点。 |
| slots.jsonl | 实际可补赛的场地和时间槽，以及不可被替换的活动。 |
| rules.jsonl | 同轮同场地只能打一局，休息按 slot 差值。tie_order 是正式判分口径。 |
| rulings.jsonl | 赛中裁决单由裁委处置；资格锁定的记录保留其当时来源。 |

## 核对资料

运行环境为 Python 3.11，使用标准库，无需下载依赖。用 `python3 -m unittest discover -s tests -v` 核对发行资料的完整性与约定的输入关系。

## 分析工具（fairplay 包）

把签表、实际阵容、种子与抽签限制、退赛与延期记录、已锁定场次放在一起，沿真实赛制比较各队晋级机会，并支持录入下一次退赛或延期做影响预览：

```
python3 -m fairplay report [--season 2026]   赛前比对 + 补赛方案 + 名额复核全流程报告
python3 -m fairplay standings --season 2024  按规则重算积分与名额，复核已公布成绩
python3 -m fairplay event --team S3          录入假设退赛，看受影响队伍与待确认决定
python3 -m fairplay event --game 2026-60     录入假设延期，看可补入的场地槽
```

### 分析口径与约定

- 积分：仅 regional 阶段对局计入晋级积分；bridge 对局只作跨赛区实力证据。played 结果计分并计实力样本；administrative 只计分；withdrawal 按规则不给分、待裁。
- 同分规则按 tie_order 依次适用；同分组两两未全部交手（如跨赛区）时跳过相互战绩；official_draw 展开为等概率分支，不把一次模拟当成确定排名。
- 机会推算：待赛对局精确枚举。H0 机会基数（全部五五开）用于章程机会差检查；H1 区内战绩、H3 种子先验等作为并存的强度解释，结论给区间。
- 共享名额：跨区比较用 积分+赛区修正，修正区间来自往届桥接对局；桥接样本小且北区均为替补出场，故按情景分别列结论。
- 补赛：只用 slots 里未占用场地槽；同场地同 slot 一局；休息按 slot 差值不小于 min_rest_slots；已锁定对阵不可改动；场地惯例 北区=roomA、南区=roomB（由历史记录归纳）。
- 退赛队伍不参与名额分配，其已赛结果仍计入对手积分；锁定资格（promoted_locked）优先占用本区名额。
- 裁决单未记赛季号，约定归属最新赛季。
